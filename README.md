# 救灾物资发放核验台

离线记录救援物资到点实数、家庭资格和现场签收，判定发放完成与缺口追索。三个独立入口为 `arrival-import`、`household-import`、`delivery-import`；各自保存原始证据、业务实体、状态和跨链决定。所有数据为离线合成 fixture，不访问网络。

安装：`python -m pip install . --no-deps --no-build-isolation`。演示：`python -m reliefhandoff demo`。测试：`python -m pytest -q`。各入口接受 `--db` 和 `--file`；`report --db` 输出逐实体状态与来源。

现场只以实际可发件数决定交付。破封包件先隔离，`arrival-reconcile` 要求两个不同见证人与实物照片摘要才能释放核点件数；少件记录保留。家庭资格按灾区、人数和凭证时效计算，`eligibility-review` 可凭独立审核证据改变待补证家庭的状态。签收量与应领额度、现场剩余数同时核对；部分签收形成原因明确的缺口，分为现场供应不足和家庭部分领取，后续补货签收才能销案。重复收据异值拒绝，冲突原文留存。`demo-decisions` 演示部分交付→破封复核→资格补证→补发销案。

## 公开统计

内部 `report` 输出家庭、签收与原始来源，仅供现场核账，不能直接对外。公开统计是独立入口，只给按站点或事先固定区域、品类、截止时刻汇总的实际已签收家庭数：同一户多次补领只算一户，原始单据、家庭标识与签名不进入任何公开结果。

- `region-define --db --code --name --sites`：在数据核证前固定跨站区域的站点集合，之后不能改站点重新定义（同集合重复声明幂等）。
- `publication-propose --db --scope --item --cutoff [--publish]`：生成一期提案。不带 `--publish` 只试发并留痕；带 `--publish` 且核证安全才正式发布。输出含明确的 `published`/`withheld` 决定、允许公开的粒度与数字（暂缓时不给数字）、所依据的全部历史公告及数据来源 blob 摘要，不含逐户清单。
- `publication-list --db`：公告与试发留痕台账。

每次试发都与全部既往公开记录一起核证，而不只比对同站上一期：对每条历史公告检查差集，并对所有公告覆盖关系组合出的韦恩原子逐段检查。跨站组合、跨期相减、同户多张收据都只能作用在这些可分辨人群段上；任何规模在 1–2 户的新增段都会使提案暂缓（保护界限 `PROTECT_K=3`，粒度与界限在核证前固定，不能看到结果后换分组试探小户数）。已发布公告不可改写，重复试发只追加留痕；迟到签收或更正只能进入下一次候选。

例：HALL 已公开 10 户，本期 11 户且仅新增 1 户时，单站发布暂缓；若 SCHOOL 同期新增 5 户且从未单独公开，按事先宣布的两站区域发布 16 户（相对 10 户差 6 户）可以发布；若 SCHOOL 的 5 户此前也已公开，`16−10−5=1` 暴露单户，区域方案同样暂缓。
